# Banking ETL Pipeline

Учебный проект по построению ETL-пайплайна для обработки банковских данных с использованием Python и PostgreSQL.

Проект демонстрирует загрузку исходных данных из CSV, очистку и преобразование данных, контроль качества и создание аналитических представлений.

> Все данные предназначены для обучения. Перед публикацией необходимо убедиться, что они синтетические и не содержат реальных персональных или конфиденциальных сведений.

## О проекте

Цель проекта — разработать последовательный процесс обработки данных, приближённый к типовым задачам аналитики и инженерии данных:

- загрузка исходных данных;
- проверка качества и связей между сущностями;
- удаление полных дубликатов;
- преобразование типов данных;
- формирование аналитических представлений;
- автоматическая проверка результатов ETL.

## Архитектура

```text

        |
        v

        |

        |
        v

        |

        |
        v

Проверки качества + unittest
```

## Используемые технологии

- **Python** — логика загрузки и управления ETL-процессом.
- **pandas** — чтение и подготовка CSV-файлов.
- **PostgreSQL** — хранение исходных, очищенных и аналитических данных.
- **SQL** — трансформации, проверки качества и аналитические представления.
- **psycopg 3** — подключение Python к PostgreSQL.
- **unittest** — автоматизированное тестирование.
- **Git** — контроль версий.

## Этапы обработки данных

1. Загрузка исходных CSV-файлов в схему `staging`.
2. Проверка исходных данных на пустые и повторяющиеся идентификаторы.
3. Проверка связей между клиентами, счетами и транзакциями.
4. Удаление полных дубликатов транзакций.
5. Преобразование строковых дат и сумм в типы `TIMESTAMP` и `NUMERIC`.
6. Загрузка преобразованных данных в схему `clean`.
7. Создание аналитических представлений в схеме `analytics`.
8. Проверка количества строк, дубликатов и проблем качества.
9. Запуск автоматических тестов.

## Аналитические представления

### `analytics.customer_summary`

Сводка по клиентам, содержащая:

- количество счетов;
- количество успешных транзакций;
- количество успешных транзакций с заполненной суммой;
- суммы успешных операций в UZS и USD.

### `analytics.transaction_quality_issues`

Представление с транзакциями, в которых обнаружены проблемы качества, например:

- отсутствующая сумма операции;
- ссылка на несуществующий счёт;
- отсутствующая или некорректно разобранная дата.

## Установка и запуск

### 1. Создание виртуального окружения

В Windows откройте CMD в корневой папке проекта и выполните:

```cmd
python -m venv .venv
.venv\Scripts\activate
```

### 2. Установка зависимостей

```cmd
python -m pip install -r requirements.txt
```

### 3. Подготовка PostgreSQL

Создайте базу данных `banking_dwh` и пользователя PostgreSQL с правами, необходимыми для создания и изменения используемых схем и таблиц.

Выполните SQL-файл `sql/01_staging.sql` в базе `banking_dwh`, чтобы создать схему `staging` и исходные таблицы.

### 4. Подготовка исходных файлов

Поместите следующие файлы в каталог `data/raw/`:

- `customers.csv`;
- `accounts.csv`;
- `transactions.csv`.

Исходные CSV исключены из Git. Для повторного запуска проекта используйте синтетические данные соответствующего формата.

### 5. Запуск ETL-пайплайна

Из корневой папки проекта выполните:

```cmd
python src/run_pipeline.py
```

Пайплайн загружает исходные данные, выполняет SQL-трансформации, создаёт аналитические представления и запускает проверки качества.

Пароль PostgreSQL вводится интерактивно. Для текущей версии необходимо заранее создать staging-таблицы и настроить права пользователя базы данных.

### 6. Запуск автоматических тестов

```cmd
python -m unittest discover -s tests -v
```

Интеграционные тесты требуют доступную базу PostgreSQL с подготовленными результатами ETL. В зависимости от реализации тестов может потребоваться ввод пароля базы данных.

## Контроль качества данных

Пайплайн проверяет отдельные правила качества, включая:

- пустые и повторяющиеся идентификаторы;
- корректность связей между клиентами и счетами;
- наличие счетов, на которые ссылаются транзакции;
- удаление полных дубликатов;
- отсутствие суммы или корректно разобранной даты;
- соответствие количества строк ожидаемым значениям.

Пайплайн не исправляет автоматически все бизнес-ошибки. Например, для транзакции `T30017` некорректная дата сохраняется как `NULL` для последующего анализа.

Успешное выполнение проверок подтверждает соблюдение реализованных правил на проверенном наборе данных, но не гарантирует абсолютную корректность всех записей.

## Ограничения текущей версии

- Используется небольшой учебный набор данных.
- Некоторые проверки привязаны к ожидаемым количествам строк текущего набора.
- Обработка некорректной даты пока содержит специальное правило для одной записи.
- Промышленное журналирование и оркестрация через Apache Airflow могут быть добавлены в следующих версиях.
- Проект не предназначен для обработки реальных банковских данных.

## Цель проекта

Продемонстрировать практические навыки работы с Python, SQL, PostgreSQL, ETL-процессами, контролем качества данных и автоматизированным тестированием для портфолио Junior Data Analyst / Junior Data Engineer.
